# V9 activation connection setup review

## Behavior and ownership

The original activation owner previously rejected every capability with any
required connection, including connections already configured in Apps. The
access step now reads bounded current original application, connection,
company-installation and relevant grant metadata for each published capability
key. Only a current initiating verified member with original `tools:admin`
authority receives observations. Instance-administrator flags do not bypass
that authority. The existing company/privacy/account/publication locks and
original five-second transaction budget remain in force.

`recorded` means current enabled configuration has an unchanged original
successful health observation, a company installation, and an authentication
record matching its original shared/personal/fallback policy. It does not mean
credentials resolve, providers remain healthy, actions are authorized, or an
Agent can execute. Dedicated Agent credentials remain pending before the
original Agent owner exists. Missing, ambiguous, changed, revoked or inaccessible
sources require review. Original Apps controls remain the place to configure
connections; activation never installs, grants, resolves credentials, contacts
providers or creates a separate setup owner.

`continue_access` rereads those original sources under Native row locks before
advancing only the original onboarding step to review. Its existing version,
request receipt, audit and account fences remain binding. The wire contains only
published requirement keys, fixed status and the original observation timestamp;
it exposes no connection/grant IDs, endpoint configuration, provider messages or
credentials. English and Danish copy distinguish connection setup from Agent
authority and representative safe testing. Unavailable legacy responses without
observations keep required connections blocked.

The explicit `Not now` alternative uses a strict `reselect_capability` command
on that same original owner. Only the access step without existing Agent,
Task, preparation or first-value references can return to capability choice.
The current request/version receipt serializes concurrent clicks, preserves the
saved outcome and company purpose, and clears only the selected publication
reference. It creates no degraded substitute task and no access records. The
customer can choose another current qualified capability or leave the saved
setup for later; the selected capability's stated purpose explains the hold.
