# V9 first-task owner bridge — 2026-10-10

Status: implementation and qualification in progress. This is a bounded part of
V9-019/V9-024 and ONB-09/10/11; it does not establish complete first-outcome or
Free Core delivery, approved starter economics, or release readiness.

The original activation flow could record an already independently reviewed
result but had no start or Stop action. This change connects an **already
prepared** original single-worker C1 internal-draft plan to the existing
`company_onboarding_runs.activation_state`. The reference contains original
installation/activation hash, Task and plan IDs. It grants no permissions.

Start requires the current qualified package and its approved original
intended-purpose deployment, the initiating verified account, current scoped
authority, an unchanged exact goal and completion contract, one untouched worker,
no retries/delegation/external tools, and the installed original Native draft
controller. The native one-call model quote and plan budget must both be zero.
Neither a paid subscription, a BYO credential, a client price nor a configured
provider supplies an AW-funded starter allowance. No allowance is invented here.

The original orchestration owner's decision function can run inside the
onboarding transaction with its outer publication accumulator. Onboarding CAS,
the original plan CAS, the first-task reference and the existing audit records
commit together. Original budget, provider, permission and cancellation fences
remain in the original owner. Dispatch happens after commit through the existing
heartbeat queue. PostgreSQL's existing governance and package run triggers derive
and preserve the run pins; the UI never creates these pins or a second queue.

A replayed original request receipt is read-only. A crash after commit and before
dispatch leaves a durable reference. Current progress is read from the original
plan and attempts. An explicit Continue requires current unchanged authority,
goal, package hash and no-charge controller, and uses the original wakeup keys.
No GET, mount or percentage display starts work. Stop records the original
owner's cancellation/outbox and remains available on feature withdrawal. Missing
session or account changes still fence Stop at the original transport boundary.

The running result reader accepts only the exact recorded installation hash,
Task and plan with current independent human worker verification. A successful
model response, saved draft, installation or completed plan alone is insufficient.

EN/DA UI shows the reviewed original task, scope, no-charge compute, original
task link, actual progress, explicit Continue, Stop and refresh. Raw current
session guards are carried from the separately qualified session-cache source.
Unknown requests retain the same body and UUID in the mounted flow.

Still required: preparation of the canonical first Task/plan through original
owners, availability of genuinely qualified no-charge compute or separately
approved starter funding, representative provider/output proof, first-agent
provisioning and the complete ONB-01–12 journey. An empty candidate list remains
truthfully unavailable. Tests of historical references and refusal do not qualify
real provider delivery. Source presence is not launch acceptance.

Validation planned: shared schema boundaries; original activation privacy and
same-request recovery; EN/DA component behavior; actual Native package,
orchestration and gateway regression with unmodified prerequisites/deadlines;
server/UI typing; token/coverage checks; built browser scenarios; final integrated
repository typecheck, full tests and build. No qualification is asserted yet.

Scoped validation now passes 143 original Native checks in four files using
actual migrated PostgreSQL and the Native artifact sandbox, with original
deadlines. Four built-browser cases pass on matching before/after source
SHA-256. Shared/UI focused checks and original server/UI types pass in their
scopes; historical fixture versions, stage and feature-dependency withdrawal

A subsequent UI correction retains Stop when the original Source owner returns
a withdrawn minimal control reference. The original current-session boundary
still disables unauthorized Stop. No withdrawn private source is rendered and
no Continue is offered. Focused authorization cases and the built-browser
withdrawn-reference case require fresh qualification for this correction.
