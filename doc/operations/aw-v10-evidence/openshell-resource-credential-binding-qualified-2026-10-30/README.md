# OpenShell resource and credential-binding qualification

The native host command now carries the compiled CPU, memory and PID limits. The host updates only the already observed immutable Docker container ID, verifies the exact resulting HostConfig, and refuses policy/start success on resource drift. Resolved credential binaries are bound through the existing signed broker claim and compared with the complete inspected provider profile; current grants, destinations and secret-version authority remain at the original broker owner.

Qualification uses separately pinned cohorts: 30 mocked host-agent tests, 66 auth/policy cases, one broker resolver test, 13 PostgreSQL host-command cases, shared typecheck and full server typecheck. All eight backend cases also executed and passed with the official v0.1.2 prover binary at the existing expected SHA-256; none were skipped in that cohort. One earlier backend attempt found stale expected fixture resource values. R6 corrects only that test expectation to the actual canonical values. Exact source snapshots, overlay pins, logs and byte-for-byte source/build restoration receipts are in qualification.tar.gz.

This is a bounded software change. Resource/credential capability flags and overall controlsHealthy remain false. The separate identity-bound lifecycle/policy patch, disk quota, arbitrary syscall controls and actual target-host probes remain open. Mocked host tests and a real policy prover do not establish Docker/kernel enforcement, physical Stop, production deployment, Human acceptance, or complete RT-01/02/03 closure.
