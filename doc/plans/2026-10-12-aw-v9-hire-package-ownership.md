# Hire package ownership

Inactive Hire preparation reviews the exact released package and one equivalent
published Role Pack inside the customer's own company. Missing, archived,
ambiguous or unsupported components block preparation; another company's
implementation is never borrowed. Confirmation atomically creates the inactive
Agent, installs the exact component through the Original package owner and
records the draft's durable preparation receipt. Package audit events join the
outer transaction and publish only after its commit. No app grants or work are
created by package installation.

The Safe Test uses that Agent's own runtime and resolved required procedures.
The canonical generated migration retains ordinary package run admission and
permits only the Original private test harness before production activation.
A deferred database constraint proves its complete test/draft/hidden-harness/
paused-plan/run correlation at commit, with zero tools, retries and delegation.
A supplied marker alone cannot create work. Terminal or Source-erased runs can
retain their existing financial liability while their payload is closed.
Publication requires the Original installation's current activation, including
its approved intended purpose, readiness, runtime, entitlement and component
checks. A recovery link opens the existing package controls. The publication C3
reassesses the package after installing the new definition in the same
transaction, so its activation hash identifies the actual published version.
Failure rolls back the version change. The immutable Original publication
receipt identifies the actual installed package version rather than mutable
draft display data.
