# Guided managed runtime request in Hire

The Hire representative-test step now offers managed runtime setup for its
actual prepared inactive Agent when the SaaS platform is installed. The
customer reviews existing included capacity and an approved runtime version.
One available qualification is preselected; alternative capacity/version
choices stay under Advanced. Separate confirmations authorize capacity use and
inactive provisioning. This does not purchase capacity, call a model, create a
model grant, bind or activate the Agent, or claim runtime qualification.

The service composes the existing V6 runtime owner. Current verified draft
creator, Agent configuration authority, company runtime management permission,
commercial entitlements, occupied capacity, protected qualification source,
report origin/date and configured host plan are checked. The Original owner
creates the encrypted Gateway secret, runtime cell and durable provisioning
operation. A body-free activity entry identifies that exact Original request.
Final authority and reviewed qualification/capacity checks happen in the same
transaction; a late withdrawal rolls back the entire request.

A repeated immutable command returns its Original receipt before new-work
admission checks. Reads remain private and scoped to the creator, company,
draft and actual Agent, including after feature rollback. A missing receipt
does not prove refusal. The latest owned Original request can be resumed after
reload without browser storage or a replacement provisioning effect. The UI
offers only receipt lookup after an unconfirmed response and hides retained
data during authority withdrawal. No new provisioning queue, host dispatcher
or model transport is introduced.

45 cases before the additional viewer/instance-admin case. This includes setup on the
actual prepared Hire package Agent, preserved inactive/package state, immutable
replay, cross-company/account denial and rollback of cell, encrypted secret,
operation and receipt after final audit or qualification withdrawal.

rejection. The built Hire journey passed two confirmations, unknown response,
exact Original receipt recovery and reload without a second effect, plus
Danish mobile reflow and automated accessibility checks. The final built
customer-copy run passed. Server/shared/UI types, token gates, module boundaries
and the coverage validator passed. Provisioning consent is withdrawn for
unsaved draft changes while Original receipt reads remain available. A final
typecheck caught the API descriptor’s missing HTTP 202 variant; its accepted
status union now matches the mounted provisioning response. The first added
permission fixture used legacy non-viewer runtime authority; the corrected
viewer fixture verifies that instance administration cannot elevate it.

Physical hosting and managed representative execution remain separately gated.
The existing bounded text-only representative-test transport does not consume
an `aw:cell` binding. This checkpoint does not advertise that managed runtime
as qualified or activate it through an unimplemented mapping. Full V9 remains
incomplete pending those mappings and the other release requirements.
