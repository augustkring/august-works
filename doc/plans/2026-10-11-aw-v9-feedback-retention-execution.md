# V9 feedback retention execution — 2026-10-11

The configured HOUSE periods currently select expiry but do not execute it.
Implement an explicit original verified internal-operator review and C3 command
for one expired case or image. Keep automatic customer retention deletion inactive.

Recheck native lifecycle, configured periods, version, current holds and actual
transport settlement under the existing short company/feedback locks. Preserve
an immutable minimal request receipt independently of the erased subject, so an
unknown acknowledgement cannot create a second erasure request. Provider calls
use the exact original object outbox outside locks; completion requires its
confirmed physical removal. Refuse an allocated PUT with unknown settlement.

Expose protected status/review and a separate confirmation in internal triage.
Hide stale private content and receipts during current-account revalidation.
Use owned historical inserts for elapsed-time fixtures, never a patched native
clock or shortened minimum retention period. Preserve original feedback, account,
company, permission, budget and timeout assertions.

Current source is under construction and unqualified. The retained receipt can
prevent ordinary SQL re-insertion; restore from a backup that lost that receipt
needs independent restore quarantine and is not qualified by this source.
Privacy registry approvals, anonymous learning, operating provider recovery and
full integrated V9 acceptance remain separate open work.
