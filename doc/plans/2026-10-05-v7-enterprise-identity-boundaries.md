# V7 enterprise identity boundary — 2026-10-05 (local implementation)

Better Auth remains the authentication authority. Pinned SSO/SCIM 1.7.2 plugins reuse the existing user, account, session and verification models. Native company policy, explicit issuer/subject bindings, company memberships and resource grants remain August Works authorization authority. Provider attributes, UserInfo email and IdP groups never become direct permissions. There is no implicit JIT or email-match linking; lifecycle mapping currently applies to explicitly approved existing non-owner native company members.

Plugin authentication/SCIM metadata is an explicit global authentication exception to company-domain row conventions, analogous to existing Better Auth accounts. Each provider has a native company FK. Every SCIM connection binds a native company policy; SCIM User/Group metadata carries that connection and provisioning domain. Group membership/projection links have native composite connection/resource FKs. Global SCIM subject metadata links a native authentication user rather than creating a second application identity.

Configured company owners prepare versioned policy drafts and explicit stable subject mappings. Platform qualification uses a current-build, protected artifact reference and expires within 30 days; it is accountable operator evidence, not automatic legal/physical certification. Existing native encrypted company signing secrets serve OIDC private-key JWT. Provider JSON contains no signing private key or client secret. SAML requires a current X.509 signing certificate, correlated requests, timestamps, signed assertions and rejection of deprecated algorithms. Public provider registration/configuration APIs are disabled. Enterprise endpoints fail closed with the default-off feature flag.

The official SCIM 1.7.2 implementation unconditionally deleted every native session when a user had no active SCIM source. That conflated SCIM-domain inactivity with global identity inactivity: the user can have unrelated August Works memberships. The narrow pinned patch `patches/@better-auth__scim@1.7.2.patch` defers that global action when the application supplies its lifecycle callback. August Works supplies the callback and changes only the approved native company membership/grants inside the framework's actual transaction. The uncustomized SDK default retains its original global behavior. This is not an override of password-reset or other global session revocation.

Native integration proof: actual Better Auth SCIM HTTP creation/deactivation against migrated PostgreSQL suspends the mapped company membership, removes its scoped grants, preserves the other company and preserves existing native sessions. Invalid bearer credentials, disabled identity and public provider registration are rejected. The tests use a local protocol fixture and operator evidence references explicitly labeled as fixtures; they do not establish live enterprise IdP, procurement, operating envelope or GA qualification.

Native guards now protect company/issuer/connection namespaces, current qualifications/flags, monotonic policy revisions, key-version pins and terminal binding revocations. Owner-approved decommissioning suspends the scoped managed non-owner memberships, revokes lifecycle mappings, removes that connection's SDK metadata and requires fresh qualification; global identities/sessions and unrelated memberships are retained. Native source guards prevent replay/restoration of withdrawn authority. The company UI uses actual member/secret selectors, a company-specific sign-in link, credential revision CAS and one-time token display without putting the token in mutation-cache results.

Signed bounded security-event delivery and V7 state portability are implemented against the existing native activity log and company export. See `doc/operations/enterprise/v7-identity-security-export-portability.md`. Security delivery is explicitly opt-in/default-off, company-filtered, schema-versioned, DNS-pinned and bounded to five cumulative attempts, 90-second leases, 1000 pending events/company and a 24-hour lifetime. Receiver deduplication handles lost acknowledgments. Native export adds shared lifecycle/evidence, all eligible observations/models (without a 100-row UI truncation), knowledge, Role Packs, Workflows, package references and governance. Privacy locks, erased-source checks, credential redaction and current owner authority apply independently of rollout/payment gates.

Open before enterprise GA: actual customer IdP sign-in/lifecycle qualification, DNS/endpoint/certificate and live receiver conformance, customer portability/exit rehearsal, contracted operating-policy enforcement, verified supplier facts, dedicated-placement/recovery evidence, AW-as-provider legal applicability assessment and procurement approval. Describing those facts in an operating envelope does not establish their enforcement. No customer-specific, physical, legal or GA qualification is claimed.
