# Private company export transfer owner

The internal durable export API extends the existing company transfer ledger. The current UI, CLI and synchronous export APIs retain their existing delivery behavior. This backend checkpoint does not qualify a public integration, a live storage provider, Cloud/local durable authority or a completed V10 release.

POST `/api/companies/{companyId}/exports/transfers` accepts the existing export selection and a UUID `Idempotency-Key`. GET the returned transfer ID for private status, then GET `.../{transferId}/download` for the server-proxied JSON artifact. All responses are private and uncached. No provider URL, object key, credential or authority reference is returned. Same-key replay retains the first operation and deadlines; changed selection is rejected. Artifact availability lasts up to the first accepted expiry. An expired artifact returns 410 and the original key cannot regenerate it.

Admission, generation, completion and reads recheck the original current Board session/key or supported Agent key/company-scope Native Run, current company permission and source selection. Human-only account and support-case selections remain unavailable to Agents. Agent key revocation, CEO demotion, loss of the responsible Human, Run cancellation and original credential expiry where applicable deny further access. Standard Agent keys have no invented expiry column. Cloud trusted headers and local implicit access are not serialized into substitute Human proofs.

The private artifact is bound to the accepted Storage namespace and exact allocated object key. Configuration changes cannot adopt or erase it through a new bucket/root. A qualified original Storage owner is required before admission. Local cleanup confirms exact object/temporary-copy absence. S3 cleanup removes exact-key versions, delete markers and current copies and verifies absence; prefix-neighbor keys are preserved. Denial, timeout or unconfirmed state retains the erasure obligation.

A running worker lease authorizes allocation and publication. A late original provider settlement or guaranteed pre-transport no-write callback may close only its original allocation, even after lease expiry; it never revives or publishes the operation. Unknown PUTs stay pinned and cannot regenerate. A failed operation with a retained artifact is terminal for that request key. Bounded recovery retries cleanup of known stored failures; only actual original-owner erasure confirmation marks the artifact deleted. Cancellation replays preserve the same export row.

Transient Source/authentication lock conflicts defer the same operation with a short cooldown. A stored artifact is reused after reauthorization; it is not uploaded again. Unknown allocations cannot enter this retry path. First accepted credential and artifact deadlines continue to bound retries. Company deletion waits on running/uncertain writes, checks original storage scope before and after prefix erasure, and preserves unresolved pins through both purge doors. Mandatory erasure does not await an unbounded local upload promise inside the cross-company scheduler.

Configured durable-execution resource policy applies to export claims through the existing shared database admission owner. Running exports and any unknown allocated write retain one active work item, including after failure, cancellation or lease expiry. Only the original write settlement or guaranteed no-write receipt releases that generation liability; retained known objects still require physical erasure. The optional policy supplies no invented quota when absent. This work-item counter does not bound aggregate generated bytes or memory.

The current source tests use actual PostgreSQL, real domain/HTTP authorization, controlled Storage boundaries and S3 SDK responses. They do not prove deployed provider behavior or WebAuthn ceremonies. Aggregate byte/generation bounds, read-only billing export delivery, remaining caller migrations, source-copy invalidation/erasure reconciliation and live operator/restore qualification remain separate release work. Ordinary upload billing/quota guards and immutable Platform Skill v3 are unchanged.
