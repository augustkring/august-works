# Identified candidate publication and activation

A separately confirmed C3 swaps the current Original Agent configuration to
exact saved content after every scenario has current Native execution and
independent human verification. Publication rechecks the baseline, model,
required procedures, creator membership, configure/wake authority, budget and
company state. Queued or running work and non-manual pauses block replacement.
The Original configuration revision owns the immutable version and durable
request receipt. Reconciliation reads that receipt without resending the action.
Editing and testing a subsequent draft keep the active version unchanged.

The canonical generated migration protects identified configuration and revision
history. Actual execution inventories and retained runtime preparation identify
the consumed revision. Historical Source deletion uses the existing privacy
markers/outbox to exclude those runs and erase copied payload and assets; the
Original financial ledger remains. The active revision cannot be removed while
its Agent references it. Original Agent removal may cascade after its parent
has been removed.

The UI shows the saved before/after instructions, responsible owner, exact
model, required procedure names and maximum future per-call cost. Publication
and activation have separate unchecked confirmations. Current authority and
scope fence late acknowledgements. An unresolved request is read by its Original
identity after reload, never automatically repeated.

Qualification is pending. This stage does not implement additional knowledge,
memory, action or delegation mappings, runtime provisioning, live provider
qualification, full integrated-branch validation or GA release.
