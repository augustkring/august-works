# Stateless draft provider qualification

Date: 2026-10-06. This qualifies the fixed server text transport; it does not
qualify an autonomous CLI, an OpenShell workload, physical provider termination
or the integrated pilot.

The existing operator conformance endpoint selects a private bootstrap driver
for a persisted `paperclip_runner` presence with provider `aw_text_only`.
SaaS startup registers this driver against the actual database and the same
deployment-pinned worker profiles used by draft admission. A request cannot
install a profile, choose a price, replace the transport or submit qualification
evidence. Local implicit operators are excluded. Ordinary Native CLI probes
continue to reject this transport.

Supply `acknowledgeProviderRuns: true`, `maximumCostCents` and an explicit
`isolationPeer` to the existing company/presence conformance endpoint. This is
an operator-requested sequence of real, potentially billable provider calls;
setting the acknowledgement in an agent configuration grants no authority.
Both presences must belong to the same logical identity and provider endpoint,
use separate native profiles, have current human configuration/wake access,
and select their exact installed stateless model qualification. Each profile
needs its own encrypted installed grant and protected current-source pricing
and full-envelope token qualification. Advertisement alone grants no admission.

The driver creates hidden native `provider_conformance` Tasks and paused,
zero-tool C0 plans. No orchestration workers or attempts are created. Their
original authenticated human, deadline and budget remain immutable financial
authority. The new `provider_conformance` purpose uses the existing model
reservation ledger. It does not consume semantic-verifier call slots. SQL and
service checks require a hidden synthetic Task, paused plan, current original
principal, explicit cost cap and zero worker/tool authority. Ordinary plan start
rejects these harnesses. They close as cancelled synthetic work, without
inventing a Task document, worker completion or customer outcome.

At most four calls exercise exact-marker routing, a fresh primary request with
no history, a fresh peer request with no history, and in-flight local
cancellation. Every request has one synthetic message and no tools, company
context, session, attachment, alternative endpoint or retry channel. The actual
encrypted credential is resolved only after a committed dispatch claim. Current
company, identity, initiating human, binding, configuration, grant and secret
version are checked before, during and after transport. Late replies are
withheld after cancellation or lost authority. Unexpected provider prose is
not copied into ordinary run records; its hash remains in the native receipt.

The combined liability across both companies cannot exceed the operator's
single USD-minor-unit ceiling. Each dispatch has a stable native run/reservation
identity and cannot be claimed again. The synthetic run records and conformance
report retain reservation IDs. Unknown or cancelled provider calls hold their
entire original maximum; no refund, resend or replacement is inferred.

`accountingBasis: native_pre_spend_liability_ceiling` means all dispatched spend
has a retained qualified maximum liability. It does **not** mean an invoice is
known. The response returns `spentCents: null`, the actual `reservedMinor` and
`unknownCharges`. An abort can confirm `localPublicationFenced`; it always
leaves `providerComputeStopConfirmed: false`. A successful conformance report
must not be marketed as physical provider stop or final billing reconciliation.
The local dispatch event qualifies the controller's event path; the provider
HTTP call remains non-streaming and no provider-streaming feature is advertised.

All required checks and current-source authority must pass before the existing
binding owner records qualification for this exact local configuration. The
peer configuration remains pinned by the native isolation proof. Report retention
checks local runtime revocation under the existing row lock. A late successful
or failed probe cannot reactivate that runtime or overwrite its retained proof.
Failed dispatched probes still close their synthetic harness and retain unknown
provider liability before the revoked report is rejected. Normal draft
plan-start/admission subsequently rechecks the installed model profile and
the actual conformance record. Live price/token qualification, protected host
evidence and the integrated customer pilot remain separate operating evidence.

The PostgreSQL suite exercises the normal operator service with unqualified
bindings, real encrypted fixture grants and real reservations. Only provider
responses and operator pricing metadata are private fixtures. It includes
combined budget exhaustion, membership/grant/configuration/flag revocation,
over-envelope usage, wrong responses, SQL bypass denial and the actual normal
draft qualification consumer. No live model calls are made by this suite.
