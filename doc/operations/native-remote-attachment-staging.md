# Native remote attachment staging and cleanup candidate

This private candidate adds a fixed, bounded staging path for Native OpenCode attachments when the runner workspace is remote. It streams bytes through a credentialless sandbox command in bounded chunks, verifies the source SHA-256 and size before publishing the workspace file, and records the exact random stage nonce with the admitted run profile. The model receives only the resulting workspace path after a verified readback.

Each write command reconstructs the current Human wake, comment, attachment snapshot, asset hash, task binding, and reader ACL. Cleanup uses a retained profile receipt bound to the original source capture and nonce, so deleting a retired temporary directory remains possible after the source is revoked. It cannot select another attachment or workspace path. Terminal lease cleanup forwards only those retained nonces to the host agent, which removes only the corresponding directories in the exact stopped run's overlay upper layer and verifies their absence. Interrupted erasure helper work is fenced by the existing Native session-erasure journal and exact helper identity.

Before the first remote write, the existing Run profile owner records an integrity-bound staging intent with the exact Run, lease, attachment source snapshot, hash, size, nonce, and derived relative path. The intent authorizes deletion only. It is marked committed only after the complete remote hash readback; it does not qualify delivered content or create a source output. Terminal and in-process cleanup can therefore enumerate a nonce even if the process stops during upload.

The stage and erasure helpers use directory file descriptors and `O_NOFOLLOW` checks for directory traversal and bounded cleanup. This candidate has not been run through the repository test suite or compiler. Host-provider-specific mounted-overlay behavior and the production runner's remote readback remain to be verified by the root agent's actual-runtime checks; no provider-wide attachment or arbitrary shell admission is introduced here.
