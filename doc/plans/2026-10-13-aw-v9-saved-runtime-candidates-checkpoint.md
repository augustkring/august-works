# Saved runtime candidates and explicit promotion

CUSTOM-09 now saves an owned runtime alternative on the canonical authoring
draft. The proposal stores metadata and exact configuration/profile/source
hashes, without copying credentials or changing the active Agent. Its immutable
creation request can be recovered through a private Original receipt read,
including after the authoring feature is withdrawn.

Qualification reuses the existing Native four-probe controller and model
reservation ledger. An explicit review identifies the current price ceiling,
isolation peer and saved version. Separate confirmations authorize the bounded
calls and their company-visible receipts. Cancellation fences local publication;
it does not claim that remote compute stopped. An unknown dispatched charge
retains its full ceiling. A repeated Original request reads its result without
another dispatch.

Representative tests consume the exact proposed configuration only after its
four actual run/debit records and current provider, peer, source and profile
pins pass. Human verification and explicit publication remain required.
Publication updates the Original Agent configuration, runtime qualification and
identified revision in one transaction. A final audit failure rolls all three
back. A subsequent draft starts from the published configuration without
inheriting a candidate belonging to an earlier draft.

Candidate construction applies the same Original configuration normalization as
Agent persistence before qualification. This fixes the mismatch found by the
new atomic-promotion integration case. Existing revision redaction remains in
place; the test does not expect private fields in revision snapshots.

The Advanced UI preserves immutable request identities through temporary
authority withdrawal and draft refresh. An unconfirmed qualification offers
Original receipt lookup, without automatic redispatch. Reads are scoped to the
current principal, company, draft and candidate and bypass browser caching.
English and Danish labels describe the separate qualification, representative
test and publication steps.

## Verification

The PostgreSQL proposal, Native conformance and publication suites passed 33
cases. The publication case exercises actual four-probe execution, a
representative model call, human verification, forced transactional rollback
and subsequent successful promotion. The affected UI/client suites passed 47
cases, including unknown requests, authority withdrawal and foreign response
identities. Server/shared/DB/UI typechecks, migration safety, module boundaries and token
gates passed. The updated Native receipt/flag-rollback, legacy migration and
API/route suites passed 45 cases. The built browser journey passed with a saved
selection, reload, lost response and Original-only receipt recovery, including
Danish mobile reflow and automated accessibility checks. The first browser
fixture used an exact wrapped-label selector that included select options; its
corrected role/name selector passed without changing product event handling.
The 70-surface coverage validator passes while preserving pending release
evidence; it does not certify whole-brief implementation.

These are software tests with synthetic provider responses. They do not claim
hosted provider qualification, a human pilot or complete V9 acceptance. Managed
runtime provisioning and broader action/channel mappings remain separate work.
