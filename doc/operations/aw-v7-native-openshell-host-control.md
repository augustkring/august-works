# August Works V7 native OpenShell host control

Date: 2026-10-05. This extends the existing V6 native host protocol; it does not authorize deployment or physical workload admission.

## Native integration

The SaaS platform registers the OpenShell backend when both `AW_RUNTIME_OPENSHELL_PROVER_PATH` and `AW_RUNTIME_OPENSHELL_PROVER_SHA256` are configured. The path must be absolute; the existing prover adapter verifies the executable bytes against that digest before each proof. Do not use a Task argument, request body or model-generated path for either value.

Host-agent 6.0.1 adds an OpenShell command lane to the existing `runtime_host_commands` table. Host-agent 6.0.2 adds immutable instance pinning. The server requires 6.0.2 before it queues or accepts sandbox commands. The original host claim endpoint selects only the original runtime command types. Signed POST requests to `/api/internal/runtime/hosts/:hostId/sandbox-commands/claim` and `/sandbox-commands/:commandId/complete` use the existing RSA request proof, credential epoch, nonce and raw-body authentication. Commands use the existing RSA-OAEP/AES-GCM envelope. No reusable provider credential is included.

Every operation pins the company, sandbox binding, native cell, generation, deterministic `aw-v7-<binding UUID>` name, image configuration, host and credential epoch. Native membership/permission and V7 flags are checked again at non-safety claim, completion and receipt consumption. Scope changes cancel pending work. Stop, provider revocation and destruction remain available after rollout rollback; enqueue still requires a current human runtime manager. The existing autonomous sandbox guardian separately uses its system-attributed native Stop path. Neither path impersonates a revoked user.

The host row serializes admission against the bounded queue capacity. Commands have a finite deadline, at most three claims and a bounded lease. Cleanup expires abandoned commands. Results are strict bounded action-specific records, with immutable completed receipts and native audit events. Concurrent requests with the same safety operation key share one command. A persisted command receipt is distinct from a runtime operation row and distinct from complete sandbox qualification.

## Private host CLI configuration

The operator's private host configuration may include `openshellCli` with `executable`, `executableSha256`, `gateway`, `workspace` and `stateHome`. It selects an existing authenticated OpenShell gateway by explicit name and workspace. Keep the CLI state directory private to the host-agent user, with no group/other permissions. The executable must belong to that user, be executable, have no group/other write permission and match the configured digest. The host checks these conditions and actual `openshell 0.1.2` version before CLI observations or effects.

The subprocess receives only the private state home, a fixed system PATH, language and no-color settings. It inherits no provider keys or insecure-TLS option. Calls use argument arrays, bounded output and deadlines. Never put a credential in a CLI argument or environment field. Install the pinned CLI and its qualified gateway metadata in the private host image/configuration using the deployment process; the agent neither downloads binaries nor creates a gateway.

Existing sandboxes must have the exact native name/workspace and `aw.company_id`, `aw.binding_id`, `aw.cell_id` and `aw.generation` labels. The controller checks them before each effect. It does not create or discover arbitrary worker-selected sandboxes. The first accepted observation persists the gateway-assigned immutable sandbox UUID before any effect. Subsequent observations, revocation steps and restart fencing require the same UUID as well as the exact native scope. A reused name with copied labels cannot replace that pin. Legacy journal entries without an observed UUID remain fenced and require operator reconciliation; the controller does not fill in their identity from a current name lookup. Stop targets one sandbox and requires an observed `Stopped` phase on that same UUID. Destruction requires a bounded, complete absence observation. Provider detach uses exact observed provider names with readiness waits and a subsequent empty attachment observation; more than four attached providers or incomplete pagination remains unsupported. Stop is attempted independently when revocation fails by the existing adapter.

The private durable journal retains receipts across restart and records only validated owned scopes for host-lease fencing. Host loss attempts both the existing cell engine and OpenShell engine even if one fails. Fencing rechecks labels and never runs a gateway-wide `--all` operation. Failed or ambiguous effects require reconciliation. The upstream V0.1.2 lifecycle CLI still sends name-scoped mutation requests without an instance-ID precondition. Before/after identity checks detect drift but cannot make those upstream effects atomic against an independently concurrent recreation. This lane remains a scoped safety controller, not an earned physical workload-admission guarantee.

## Remaining physical controls

This CLI controller deliberately returns no capability snapshot and unsupported probe observations. CLI resource metadata and configured image labels do not prove an observed image, custom syscall/process controls, disk/PID/wall-clock enforcement or company/presence/destination/expiry/revocation-bound credential use. Prepare, policy apply and workload admission remain closed until those controls have a real native implementation and target-host qualification. An unavailable qualification is retained as an inconclusive report with an explicit native cell reference, without manufacturing physical image evidence.

Local PostgreSQL and injected CLI tests cover actual native queue, authorization, encryption, drift, cancellation, replay, unsupported qualification, private configuration and scoped effects. They are fixtures, not protected physical or live-customer evidence. The integrated pilot manifest therefore retains the OpenShell implementation blocker. Complete the outer enforcement and credential-use broker before attempting a managed workload on qualified staging.
