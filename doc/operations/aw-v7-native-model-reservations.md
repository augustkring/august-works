# August Works V7 native model reservations

Date: 2026-10-05. This implements the internal ledger and dispatch claim. The [read-only model consumer](aw-v7-read-only-model-consumer.md) uses it for independent assessments. The [forced Native draft controller](aw-v7-native-draft-launch.md) also uses this ledger for its bounded internal drafts. Broader autonomous CLI/session transport remains unqualified. No actual pricing profile or vendor account is installed in workspace verification.

The broker accepts an operator-qualified immutable tariff ceiling through its private native registry callback. A request cannot supply its own tariff. Provider, exact model, USD minor units, input/output ceilings, fixed charge, current deployment SHA, qualification hash and finite expiry are pinned. Quotes round the aggregate charge upward using integer arithmetic. Token envelopes must be finite integers and are bounded. Unknown, expired, future or wrong-revision pricing stays closed. Converting input text to a proven billed-token upper bound remains the responsibility of the qualified provider consumer; character estimates and post-spend cost events are not a hard cap.

Migration 0379 adds company/plan-scoped `orchestration_model_reservations` under the existing Orchestration Plan. It reuses `model_cost_reserved` and the accepted plan's `maxModelCostMinor`. Native PostgreSQL locks serialize concurrent admission; an INSERT trigger debits the counter exactly once. The counter must match the immutable cumulative ledger, cannot decrease, and cannot exceed the explicit cap. The original principal, current canonical Task, rollout, source authority, tariff and deadline are checked again before dispatch. C4 remains closed. The worker/attempt foreign keys preserve native company and plan relationships.

An idempotency key binds the immutable inputs and quote. A dispatch claim commits before an SDK call and can be consumed only once. A crashed, timed-out or otherwise unknown dispatch retains its entire conservative debit. Expired unused reservations also retain the cumulative debit. This can leave less usable budget than actual spend; it prevents retry/refund races from reopening an unproved charge. There is no automatic retry after an ambiguous request. A provider transport outcome never completes a Task or certifies business evidence.

The ledger stores only input/authority/response hashes, native references, quote metadata, bounded usage counters and statuses. It stores no prompts, generated response bodies, provider credentials or provider error bodies. Inputs and terminal financial receipts are immutable. Plan erasure closes future admission while retaining minimal native budget metadata. Plan deletion cascades its ledger; individual debit deletion while the plan exists is rejected.

Local PostgreSQL tests verify concurrent oversubscription, replay, changed input/price/source, permission loss, dispatch claims, immutable receipts, expiry and unknown-outcome debit preservation. Tariffs and authority callbacks in those tests are explicit private fixtures. They do not prove real vendor prices, actual billed-token bounds or provider enforcement.

Migration 0380 allows the separately qualified read-only consumer to reserve against a nullable monetary cap while charging the existing finite verifier-call allowance. Explicit monetary caps remain mandatory for worker reservations and are enforced whenever present. The bounded expiry sweep runs independently of rollout and profile configuration.

Worker plan-start/admission requires every model call to use its qualified credential/price broker. The private `aw_text_only` controller supports one declared C0/C1 internal draft with an explicit cap and current source/profile qualification. Managed autonomous CLI/session admission remains closed. Read-only assessment transport does not establish worker CLI or workload credential enforcement. Do not enable a cap by removing admission checks or manually editing qualification metadata. The integrated pilot blocker remains open.
