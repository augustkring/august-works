# OpenShell admission lifecycle: software qualification

The 27-file source boundary binds protected preflight and provisioning receipts, canonical qualification probes, one-use credential canaries, current physical-policy observations and admission epochs through the existing sandbox owners. Stop revokes the old policy. A later start needs a fresh policy, current authority and an expiry no later than the original same-manifest/root deadline. Replays observe the existing claim; new admissions have distinct effect keys. Business data is preserved during compatible reauthorization; incompatible static policy requires the existing replacement/recovery path.

The frozen R14.36 source passes shared and DB builds, 59 host tests, 73 policy/JWT tests, 37 PostgreSQL bridge/fault tests, and shared/server typechecks. The complete raw receipt and exact source pins are archived here. Qualification used the pinned overlay on the recorded dirty baseline; it is not a final unchanged-head workspace qualification. All source, compiled outputs and tsbuildinfo were restored byte-for-byte after qualification. The heartbeat setup_failed log belongs to a deliberately cancelled successor during teardown; its late failure finalization is skipped, executions are drained and no unhandled rejection was reported.

Forward migrations 0567 and 0568 keep historical SQL intact. The first requires all 19 unique passing probe cases and rejects missing/null fields. The second permits a fresh qualified policy for a currently stopped binding/cell while keeping the previous policy revoked.

These are controlled software and transport checks. They do not qualify a physical host, kernel, installed release image, live provider, production fleet or Human/operator acceptance. Long-running model credential refresh, the host conversation-token scope, the guarded Relay fixture and the whole Native retained-source suite remain separately under implementation. No merge, deployment or package publication is claimed.
