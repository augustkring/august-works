# Native decision outcome reviews — implementation in progress

The existing native Decision, its human choice and its surviving prospective
context binding own every review. The API cannot invent a retrospective baseline
for an older or unbound decision. One review per bound Decision tracks scheduled,
in-review and terminal completed/inconclusive/cancelled states with revision CAS.
`due` is a read-time view of the frozen chosen option's latest declared review
date. This adds no scheduler, automatic decision, Foundation change or side effect.

Each transition appends an immutable human receipt with exact baseline hash,
actor/time, rationale and native lineage. SQL rejects bare status changes,
inconsistent due dates, changed baseline/choice, mutable receipts and terminal
rewrites. Source-owned receipt erasure removes the aggregate and older review
prose. It works through existing analytical retention, native source erasure and
company purge with flags off or a paused company; the canonical choice survives
analytical source erasure. Migration 0398 uses the native generated journal and
snapshots and additionally checks context/preparation-before-choice chronology
and membership of the frozen option in the native signed options.

Final reviews separate six explicit assessments: decision process quality,
assumption accuracy, execution fidelity, external change, observed outcome and
causal confidence. Human judgments are labelled as judgments. Every frozen
assumption receives an explicit supported/contradicted/inconclusive assessment.
Review prose and later observations never overwrite the pre-choice assumptions,
rationale or expected range. The native effect execution status is captured
separately from business outcomes; successful execution is not business success.

Actual measurements are captured by the native metric owner, not supplied as
values, timestamps or hashes by the caller. They must be observed after the
canonical choice. A numeric comparison requires the same exact metric version
and unit, the exact declared horizon window and observation after that horizon
has elapsed. Completed review requires all chosen expectations; unavailable
measurements and an unfinished/invalid prospective horizon cannot be called a
completed quantitative outcome. Inconclusive review remains available.

The server computes below/within/above range position and observed direction.
The range remains a human expectation, not a calibrated forecast interval.
Created-object cohorts can differ between baseline and outcome windows; current
lifecycle state is observed at capture. Before/after association does not identify
the effect of a Decision. No causal claim reference is admitted until a qualified
native causal evidence owner exists. No outcome automatically scores the quality
of the original choice or creates a person/employee score.

Historical review reads return captured observations and recheck current purpose,
baseline, source ownership, hidden Tasks, project ancestry, suppression and
retention. They do not recompute historical values using current status. Bounded
material: 20 actual pins, 16 chosen expectations, 20 assumptions, three lifecycle
receipts, 20,065 lineage edges, 30-second source budgets and 8-second statements.
Metadata-only native audit events contain status/revision, not review prose.

Source validation is recorded under `/var/tmp/aw-v8-decision-outcome-*`.
The 70-test migrated-PostgreSQL/native selection passes: ten outcome review
checks, ten prospective-context checks, 34 existing Decision checks, native
company purge and 15 OpenAPI checks. It includes later-only source erasure,
genuine short-horizon measurement chronology and due derivation without writes.
Three strict shared contract tests, snapshot drift, migration safety and server
type checking pass. These are local source checks, not integrated or hosted
acceptance.
The native Decision context panel now includes explicit schedule/begin/cancel
controls, six human judgments, assumption validation, compatible native metric
pickers and immutable historical review display. Parent and review polling pause
while the human edits; account/privacy changes and server errors clear sensitive
views. Incomplete evidence permits abstention but cannot silently fill values.
The current UI passes 27 component checks, token gates and the Storybook build.
All 54 browser checks pass across context/review states, two themes and
mobile/desktop widths, WCAG axe, keyboard provenance, form boundaries and both
31-second unsaved-edit regressions. Screenshots were inspected locally; this
does not qualify the maintainer visual baseline or live full-stack deployment.

Native Routine reminder attachment, Decision-to-Learning conversion,
templates, AI assistant, other analytical evidence owners and integrated/hosted
qualification remain open. Existing V7 Learning requires verified Memory roots
that resolve to actual canonical completed Task outcomes; this review owner does
not relabel free prose as verified outcomes or bypass that requirement.
