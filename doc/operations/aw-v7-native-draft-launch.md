# Forced Native internal draft launch

Date: 2026-10-06. This is a bounded controller implementation, not a managed
autonomous runtime qualification or a completed customer pilot.

The persisted agent must use `paperclip_runner` with provider `aw_text_only`,
the exact installed `workerModelProfileId`, its qualified `model`, a bounded
`maxOutputTokens` and the `per_turn` lifecycle. It has the distinct Native driver
`aw_text_messages`. Provider configuration cannot select a tariff, destination,
key, shell, provider session or alternative backend. CLI AI bindings and adapter
environment credentials are rejected. The ordinary model catalogue returns no
CLI fallback. The UI identifies an already configured agent as an internal
draft for review; it does not offer this private profile as an ordinary provider.

The existing private worker-profile loader supplies the operator-owned profile.
SaaS startup registers its gateway against the actual database instance. No
request body or browser route can install this authority. A missing registration,
expired/source-changed tariff, stale native conformance, changed provider config,
revoked encrypted grant, inactive presence or lost initiating-human access denies
qualification before model spend. Static Native discovery advertises the fixed
contract without probing or manufacturing a report. Normal CLI conformance
rejects this provider. A production operator still needs actual retained
conformance and protected qualification evidence for this exact source/profile.

Plan start holds the original plan lock and checks every remaining worker, its
canonical assignment/topology, current contract and initiating human. Each worker
must have one declared output and enough remaining model cost and two Task tool
actions. Each Native admission repeats qualification with the original principal.
There is no new scheduler, reservation ledger, checkout owner or completion
authority. The existing PostgreSQL model reservation occurs before credential
resolution and provider dispatch; each actual Native Task handler uses the
existing tool invocation ledger before its effect.

The actual heartbeat selects the private draft backend before Native dispatch.
Its ordinary provider test seam cannot substitute another backend for a draft.
Runnerd, managed sessions, continuation, replacement, delegated scopes and raw
MCP are outside this path. The factory binds the exact running Native session,
attempt/worker/manifest, initiating human, company and retained completion
contract. It reads only the server's content-addressed instruction and assigned
Skill bundles. The manifest, file hashes, root, sizes and UTF-8 bytes are verified
within a bounded envelope. Arbitrary host roots, symlinks, tampering, binary data
and oversized bundles are rejected. The text does not grant executable access.

One metered Task read precedes one reserved model call. The controller writes
one canonical declared Task document with optimistic revision control and the
second tool debit. The draft driver has its own server-selected control-plane
event stream, separate from the coordinator's stream. Model text cannot choose
event identity, destinations or protocol/tool commands. The real Native result
proposes `needs_review`, unknown criteria and no completed objective. Existing
Native finalization preserves server completion authority and human review.

Current authority is checked during the provider call and before publication.
Human Pause, revocation or ambiguity withholds the draft, retains the financial
reservation and uses the existing native Stop outbox. A requested Stop is not
proof of physical termination. Stable run/call identities prevent automatic
resend, including after restart. A new attempt requires current reviewed
authority and remaining cumulative budgets; counters cannot reset.

Acceptance uses migrated PostgreSQL, real encrypted grants, plan decisions,
Native admission, the actual heartbeat, event ownership, financial/tool guards
and the canonical document handler. Provider responses and conformance/pricing
metadata are explicitly private fixtures. Physical OpenShell controls, per-use
workload credential enforcement, live account qualification and the integrated
pilot remain separate incomplete boundaries.
