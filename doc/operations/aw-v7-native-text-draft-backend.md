# Native text draft backend

The private `aw-text-draft-v1` backend implements the existing Native Session
contract for one internal draft. It binds the actual company, presence, run,
admitted worker/attempt/manifest and current plan version. Opening performs one
metered canonical Task read. One bounded inference uses the existing private
worker gateway and its committed financial reservation. The existing Native
Task handler saves the declared output using optimistic document revision
control and charges one tool action. The model receives no executable tools,
provider keys, shell, file access or destination selection.

Native events identify the control plane as their actual source. The retained
result has `needs_review`, unknown criteria and no completed objective or
invented check. It references the real Task document endpoint and saved revision.
Events and session snapshots contain neither the draft body nor the provider
credential. The ordinary canonical Task document and existing Native mutation
receipt remain subject to their existing privacy and erasure rules.

One fresh default turn is permitted. Session reopening, continuation, plan turns,
automatic recovery and replacement are rejected. Stable run/call identity and
the existing ledgers prevent automatic resend after restart or lost responses.
Cancellation revokes local turn authority synchronously, aborts the transport,
settles event iterators and prevents later draft/result publication. Canonical
mutations recheck that controller-owned signal under their existing locks and
roll back if it is revoked before receipt persistence. Already acquired or
committed effects remain subject to ordinary native ambiguity handling.

Provider ambiguity, empty output, changed authority or inability to publish the
declared draft requires human resolution. The private controller failure path
uses the exact Native attempt binding to pause and enqueue native Stop even
after original-user revocation or capability expiry. Completed or unknown model
charges are retained. No accepted Stop request proves physical termination.

The backend is exercised against migrated PostgreSQL, the actual encrypted AI
grant, actual financial/tool ledgers and real Task handlers. Only the provider
transport response and qualification metadata are private fixtures. Production
selection is not wired yet. It advertises no runtime-context capabilities and
cannot qualify or replace the existing autonomous CLI providers. Explicit
provider identity, bounded realization of assigned instructions/Skills/MCP,
start/admission qualification and the actual heartbeat launch remain required
before capped production plans can start. Physical OpenShell and credential-use
qualification remain separate incomplete boundaries.
